# 이트라이브 개발 오케스트레이터 (etrial-dev)

## 목적

e-able-a11y 프로젝트의 개발 작업을 적절한 에이전트에게 위임하고 품질을 보장하며 결과를 통합한다.

## 에이전트 배정 기준

```
작업 유형 판단
├── 감사 엔진/서비스/API → audit-dev
├── UI/컴포넌트/CSS → ui-dev
├── 테스트/검증 → qa
├── 감사 엔진 + UI → audit-dev + ui-dev (병렬)
└── 전체 기능 (엔진+UI+테스트) → 3명 순차 또는 병렬
```

## 오케스트레이션 패턴

### 패턴 A: 단일 에이전트 (단순 작업)

```
1. 작업 유형 확인 → 담당 에이전트 선택
2. Agent(audit-dev | ui-dev, model: "opus") 호출
3. 결과 검토 후 qa로 검증 요청
4. 최종 보고
```

### 패턴 B: 병렬 (독립적 기능)

```
1. 백엔드/프론트엔드 분리 가능 확인
2. audit-dev + ui-dev 동시 실행 (run_in_background: true)
3. 양쪽 완료 후 qa로 통합 검증
4. 최종 보고
```

### 패턴 C: 순차 (의존 관계 있음)

```
1. audit-dev → 타입/API 먼저 구현
2. ui-dev → API shape 받아 UI 구현
3. qa → 통합 검증
4. 최종 보고
```

## 실행 절차

### Step 1: 작업 분석

```
- 어떤 파일/모듈이 영향받는가?
- 새 타입이 필요한가? (src/types/index.ts)
- 엔진/UI 의존 관계가 있는가?
- 기존 테스트가 깨질 위험이 있는가?
```

### Step 2: feature-plan 실행 여부 결정

- **2시간 이상 작업** → feature-plan 스킬로 계획 먼저 수립
- **간단한 버그 수정/소형 추가** → 계획 없이 바로 에이전트 위임

### Step 3: 에이전트 호출

모든 에이전트 호출 시 `model: "opus"` 명시.

```
Agent 호출 시 프롬프트에 반드시 포함:
- 구현할 기능의 명확한 범위
- 관련 파일 목록
- 준수해야 할 규칙 (.agent/rules/ 참조)
- 출력 파일: _workspace/{agent}-output.md
- qa가 검증할 포인트
```

### Step 4: QA 검증

각 에이전트 작업 완료 후 qa에게 검증 요청:
- 검증 대상 파일
- 관련 KWCAG 항목 (UI 작업 시)
- 실행할 테스트 커맨드

### Step 5: 완료 보고

사용자에게 보고 시:
- 변경된 파일 목록
- 품질 게이트 통과 여부
- 남은 작업 또는 주의사항

## 중간 산출물 관리

```
_workspace/
├── audit-dev-output.md   ← audit-dev 구현 요약
├── ui-dev-output.md      ← ui-dev 구현 요약
└── qa-report.md          ← qa 검증 결과
```

## 에러 핸들링

| 상황 | 대응 |
|------|------|
| 에이전트 구현 실패 | 에러 원인 파악 후 수정 지시, 재시도 1회 |
| QA 게이트 실패 | 해당 에이전트에 수정 요청 (구체적 항목 전달) |
| 타입 충돌 | audit-dev가 먼저 타입 확정 → ui-dev 재작업 |
| 빌드 실패 | 빌드 오류 내용 audit-dev/ui-dev에 전달 |

## 테스트 시나리오

### 정상 흐름 (중간 규모 기능)

1. "Notion 저장 시 페이지 제목을 자동으로 날짜+URL로 설정해줘"
2. → `feature-plan`으로 2단계 계획 수립
3. → `audit-dev`에 NotionService 수정 위임
4. → `qa`에 NotionService.test.ts 검증 요청
5. → 테스트 통과 확인 후 완료 보고

### 에러 흐름 (타입 불일치)

1. `audit-dev`가 `AuditResult`에 새 필드 추가
2. → `ui-dev`에 타입 변경 알림
3. → `ui-dev` 컴포넌트 props 업데이트
4. → `qa`에 타입 경계면 검증 요청
5. → 빌드 성공 확인 후 완료 보고
