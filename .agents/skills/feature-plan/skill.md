# 기능 플래너 (Feature Planner)

기존 `.agent/skills/my-skill/SKILL.md`의 내용을 이 프로젝트에 맞게 통합한 버전이다.

## 목적

각 단계가 독립적으로 동작하고 롤백 가능하며, 품질 게이트로 검증된 TDD 기반 실행 계획을 `docs/plans/PLAN_<기능명>.md`로 생성한다.

## 실행 워크플로우

### 1. 코드베이스 분석

1. 관련 파일을 읽고 영향 범위를 파악한다:
   - 감사 엔진 관련: `src/lib/`, `src/services/`
   - UI 관련: `src/features/`, `src/components/`
   - API 관련: `src/app/api/`
   - 타입: `src/types/index.ts`
2. 기존 테스트 패턴(`src/**/__tests__/`)을 확인한다.
3. 코딩 컨벤션 영향 범위(`.agent/rules/`)를 파악한다.

### 2. 에이전트 배정 결정

작업 유형에 따라 담당 에이전트를 명시한다:

| 작업 영역 | 담당 에이전트 |
|-----------|-------------|
| 크롤러, 감사기, KWCAG 매핑, API | `audit-dev` |
| React 컴포넌트, CSS, 페이지 | `ui-dev` |
| 테스트 작성, 접근성 검증 | `qa` |
| 복합 기능 | 복수 에이전트 병렬 또는 순차 |

### 3. TDD 기반 단계 분할

3~7개 단계로 분할하며 각 단계에:
- **RED 작업**: 먼저 실패하는 테스트 작성
- **GREEN 작업**: 테스트를 통과시키는 최소 구현
- **REFACTOR**: 코드 품질 개선 (테스트 성공 유지)
- **품질 게이트**: 다음 단계 진입 조건

### 4. 계획 문서 생성

`docs/plans/PLAN_<기능명>.md`를 아래 구조로 생성한다:

```markdown
# PLAN: <기능명>

> **목표**: <한 줄 목표>
> **담당 에이전트**: <audit-dev / ui-dev / qa>
> **최종 업데이트**: <날짜>

## 아키텍처 결정

<결정 사항과 근거>

---

**중요 지침**: 각 단계 완료 후:
1. ✅ 완료된 태스크 체크박스 체크
2. 🧪 품질 게이트 검증 실행
3. ⚠️ 모든 항목 통과 확인
4. 📅 최종 업데이트 날짜 갱신
5. ➡️ 그 후에만 다음 단계로 진행

⛔ 품질 게이트를 건너뛰지 마세요.

## Phase 1: <단계명>

**목표**: <인도물>
**담당**: <에이전트명>
**예상 시간**: <1~4시간>

### 태스크
- [ ] RED: <실패 테스트 작성>
- [ ] GREEN: <최소 구현>
- [ ] REFACTOR: <개선>

### 품질 게이트
- [ ] `npm test` 전체 통과
- [ ] TypeScript 에러 없음
- [ ] ESLint 통과
- [ ] <도메인별 항목>

### 롤백 전략
<되돌리는 방법>
```

### 5. 사용자 승인 후 생성

계획 초안을 먼저 보여주고, 승인 후 파일을 생성한다.

## 이 프로젝트의 품질 게이트 표준

**공통:**
- [ ] `npm run build` 성공
- [ ] `npm test` 전체 통과
- [ ] ESLint 오류 없음
- [ ] TypeScript 에러 없음

**감사 엔진 작업 시 추가:**

- [ ] Playwright 브라우저 실행 성공

**UI 작업 시 추가:**

- [ ] 키보드 단독 조작 테스트
- [ ] 색상 대비 4.5:1 이상
